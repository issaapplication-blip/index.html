# RAFIQ — نظام أكواد الخصم أحادية الاستخدام

## فصل المنصة عن قنوات التواصل

الموقع العام لا يتصل ببوت Telegram ولا ينشر في قنوات Telegram أو WhatsApp ولا يرسل رسائل عبر WhatsApp. التواصل مع العملاء والمراكز وإدارة الحالات يتم بصورة مستقلة بواسطة الإدارة عبر Telegram وWhatsApp اليدوي.

## اعتماد المركز والإعلان

1. مراجعة بيانات المركز ونوع الخدمة والمنطقة.
2. إتمام الاتفاق والتعاقد مع المركز.
3. اعتماد الإعلان والعرض وقيمة الخصم وتاريخ البداية والانتهاء وشروط الاستعمال.
4. نشر الإعلان على `announcements.html` فقط بعد موافقة الإدارة.
5. عدم نشر كود الخصم العام أو إدراجه في الإعلان.

الفئات المعتمدة في صفحة الإعلانات:
- المختبرات الطبية.
- مراكز التصوير الطبي والأشعة.
- مراكز العلاج الفيزيائي.
- مراكز بيع وتأجير المعدات الطبية.

## إصدار كود للعميل

- تُراجع الحالة عبر Telegram أو WhatsApp من قبل الإدارة.
- يصدر كود عشوائي غير قابل للتخمين مرتبط بمركز واحد وعرض واحد وعميل/حالة واحدة.
- يسجل النظام قيمة الخصم ونوعه وتاريخ انتهاء الصلاحية وشروط الاستخدام.
- يرسل الكود للعميل بشكل خاص فقط.
- لا يظهر الكود على الموقع أو في القنوات العامة.

## الاستخدام لمرة واحدة

عند حضور العميل إلى المركز، يؤكد المركز الكود للإدارة عبر قناة التواصل الخاصة المتفق عليها. تسجل الإدارة عملية الاستخدام في Telegram admin workflow. يجب أن يكون تغيير الحالة إلى `redeemed` ذريًا في قاعدة البيانات، بحيث لا تنجح إلا أول عملية استخدام:

`issued → redeemed`

والحالات البديلة:

`issued → expired` أو `issued → cancelled`

أي محاولة ثانية يجب أن تعيد أن الكود مستعمل مسبقًا أو غير صالح. يجب حفظ وقت الإصدار والانتهاء والاستخدام والمركز والعرض ومعرّف المدير الذي اعتمد العملية، مع عدم تخزين تشخيصات أو بيانات صحية غير لازمة.

## المتطلبات قبل التشغيل الفعلي

يتطلب النظام جدولًا خاصًا في Supabase، وRLS يمنع القراءة والكتابة العامة، ودوال RPC إدارية لإصدار الكود وإلغائه واستخدامه ذريًا، وأوامر Telegram مقيدة بمعرّفات المديرين. لا يجوز اعتبار الأكواد أحادية الاستخدام مفعّلة قبل إنشاء البنية واختبار محاولتي استخدام متزامنتين.

لا تُطبّق أي migration أو تعديل على قاعدة بيانات Supabase ضمن تعديل الواجهة هذا. لم تصدر أكواد خصم حقيقية بعد.
